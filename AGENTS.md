# Multi-Tenant SaaS "Golden Rules" (AGENTS.md)

## 🏗️ Project Overview
A secure, siloed SaaS platform for automated financial analysis. The architecture ensures total data isolation between businesses (tenants) using Identity Platform and Firestore subcollections.

## 📁 Repository Structure
- `/public`: Frontend (Vanilla JS, HTML5, CSS3). Multi-tenant aware UI logic.
- `/functions/src`: Backend (Node.js, TypeScript). Core processing and administration logic.
- `/firestore.rules`: Security rules enforcing `businessId` isolation.
- `/storage.rules`: Security rules enforcing `tenants/{businessId}` isolation.

## 🔐 The "Golden Rules" of Development

### 1. Data Isolation (The Silo Rule)
- **Database**: NEVER query a top-level collection for business data. Always query through the business silo: `/businesses/{businessId}/receipts/...`.
- **Filtering**: Every Firestore query MUST include a filter for `businessId` if triggered by a user.
- **Storage**: Files MUST be stored at `tenants/{businessId}/drivers/{uid}/receipts/{filename}`.

### 2. Identity & Context
- **Custom Claims**: All authenticated users MUST have a `businessId` and `role` (admin, bookkeeper, driver) in their JWT.
- **Tenant Context**: Before sign-in or password reset, use the `/user_lookup/{email}` collection to identify the user's tenant and set `auth.tenantId`.
- **Tenant-Aware SDK**: Use `auth.tenantManager().authForTenant(businessId)` in Cloud Functions for user management.

### 3. AI Extraction (Dynamic Schema)
- **Prompting**: Gemini prompts must be dynamically generated by merging the `RECEIPT_SCHEMA` with custom fields found in `businesses/{businessId}/schema_definitions/`.
- **Validation**: All AI-extracted data must be normalized and validated against the business's active schema.

### 4. Deprecation Policy (Legacy Cleanup)
- **Google Sheets**: ALL logic referring to `google-spreadsheet` or Google Drive API is DEPRECATED. Do not suggest or implement Sheets-based features.
- **Global Collections**: Top-level collections like `receipts` or `batches` (without business scoping) are DEPRECATED.

## 🤖 Interaction Guidelines for Jules
- **Audit Mode**: When performing an audit, prioritize checking for "Data Leaks" where a `businessId` filter might be missing.
- **Security First**: Ensure all new functions check for `request.auth.token.businessId` consistency.
- **Naming Conventions**: Use `camelCase` for variables and `kebab-case` for file names in `/functions`.
